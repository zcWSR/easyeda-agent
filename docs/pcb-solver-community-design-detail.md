## 数学模型与当前接口

对模块 `m`，选择允许位姿 `p ∈ P_m`，二元变量 `z[m,p]` 满足 `sum_p z[m,p] = 1`。位姿包含平移和允许角度，当前模型固定装配面。成员、真实焊盘及显式归属的内部铜共用原始 anchor 变换；锁定、板框、净距、禁布区和所有权是硬约束。动态邻域按声明步长与半径产生 `P_m` 的候选，不证明遍历了全部位置。

固定一个布局后，在由位置、铜层和到达方向构成的图上选择路径。二元变量 `x[k,e]` 表示需求 `k` 使用有向边 `e`。中间节点流入等于流出；起点净流出 1，终点净流入 1；还需约束节点度数与环路，确保选中边构成需求路径，不能只靠流守恒。不同网络存在铜净距冲突的边对满足 `x[k,e] + x[j,f] <= 1`。过孔是带尺寸、跨层和预算约束的连接。多端网由明确端点需求覆盖；未来的树拓扑优化不能借端点对各自成功声称整网共同连通。

现有实现是有界启发式搜索。局部修复的合法候选按以下事实向量依次排序：移动组数、总位移、旋转数、新增过孔、实际线长、转折数。它适合尽量少改已有板；从零布局必须另行声明目标。可行、搜索完成、模型内最优是三个不同结论；预算耗尽或部分路线不构成全局无解或完整成功。

当前局部修复允许保留未受影响对象的既有机械 finding，涉及移动对象的问题不能变差或沿用重叠豁免；因此候选 `pass` 也不代表整板 DRC 已清零。贡献者须保留这一基线比较语义，报告检查范围。

## 本地开始与提交要求

使用 `go.mod` 指定的 Go 版本，从 `dev` 建立贡献分支，PR 默认以 `dev` 为目标。算法包测试无需 Node、Python、EDA 登录或硬件：

```bash
make pcb-solver-test
go test ./pkg/pcbsolve -run '^TestFileCases$' -v -count=1
go test ./pkg/pcbrouting ./pkg/pcbsolve -run '^$' -bench . -benchmem -count=3
```

`pkg/pcbsolve/testdata/<case>/` 的 `board.json` 是公共 `pcbmodel.Board`，`request.json` 是 `pcbsolve.Request`；与 EasyEDA 原始 `pcb dump` 的 JSON 不是同一格式。四包可以直接用这些文件测试；CLI 使用宿主快照并通过 `internal/app/pcb_solve_adapter.go` 转换。不要把公共模型文件直接传给要求原始 dump 的 CLI。

文件案例包括来源/起点/参数/单位/验证状态说明、板模型、独立需求及期望。`TestFileCases` 自动发现目录；期望写约束、候选数量和事实指标，不把某次求解器坐标当唯一正确答案。新增期望字段时一并扩展严格解码与断言。`fixed-route-order/witness.json` 展示如何另附可审查的合法路径见证。

每个 PR 提供原基线与新代码 commit、输入哈希、搜索参数/预算、全部运行结果，以及独立 `Check` 的结果。正确性先通过，再比较共同布通率、目标向量、状态、耗时和内存。比较布局策略固定 Router，比较 Router 固定布局；预算、机器、线程与随机种子事先固定，失败不能被计作零线长。公共包 CI 是快速入口，完整仓库 CI 仍需通过。

## A1：独立的小型精确参照与基准案例

**建议 Issue 标题**：`test(pcb): add an independent exact oracle for tiny joint layout-routing cases`

目标：给 2～4 个移动组、少量位姿及极小离散路由图，独立枚举合法位姿和共同路径，报告该明确有限模型的可行性、最优目标向量和搜索是否穷尽。可以先提交测试辅助程序与一个正例/负例，不修改生产搜索器；后续再扩充文件式基准。

验收：参照不能调用生产 `Solve`，并用可人工审查的独立路径集合或独立几何判定避免同源缺陷；只有完整穷举才能标模型内最优/无解。受限的预定义路径集合只证明该集合，超时保持未知。用参照核对生产候选的合法性和质量差距，已知可行但当前漏解的案例单列为挑战集，不能伪造生产通过断言。默认四包测试无需外部求解器；可选离线实验若用其他语言/求解器，依赖和复现入口另列。

## A2：同层多候选路线与搜索预算改进

**建议 Issue 标题**：`feat(pcb): explore bounded alternative routes on the same copper layer`

入口：`pkg/pcbsolve/geometry.go:routeCandidates` 目前每个允许层调用一次 `pcbrouting.Solve`；`SolveJoint` 已能对返回候选和排网顺序回溯。先用独立合法 witness 找到“换序仍不足、需要同层替代路径”的最小反例，再改候选生成；不要重新实现已有多网协调器。

范围：有界的多路径候选、拥塞引导或局部撤回重寻均可，保持现有请求和单网 API 兼容。全部提案、单次寻路和协调搜索计入共享预算；取消与资源不足不能伪造成几何阻挡。每条候选用完整铜宽/净距检查，多条候选通过 `CheckJoint` 和 `pcbsolve.Check` 复验。

验收：反例由失败转为共同通过，现有六个文件案例和篡改/预算/固定组负例不退化；固定输入可复现，平移/旋转/乱序测试符合等价约束。保留同预算前后结果，列出增加的时间或内存，不凭一个成功例宣称全局最优。扩展过孔落点或大规模性能另拆 PR。

## A3：拥塞感知的初始布局候选

**建议 Issue 标题**：`feat(pcb): seed group placement using routing demand estimates`

对应 LG-16。当前已有“布局后共同试布，冲突反馈让位”；本项在精确共同试布前，用模块间连接方向和通道需求改善种子或候选顺序。保留完整组、固定轴、允许姿态和真实几何。估计只能引导搜索；未经证明的估计不能排除合法方案或替代 `Check`。

验收：与冻结的现有候选策略使用相同 Router、相同预算和完整案例集；做启用/关闭估计的对照，报告共同布通率及真实路径指标。至少保留一个“估计很好但实际不可布”的负例。局部修复继续使用原最小移动目标；从零布局作为独立范围，先定义用户关心的目标，不悄悄替换当前排序。

## 宿主集成由独立任务推进

LG-18 的历史 `auto-place`、专用策略和旧 JSON 兼容迁移仍可贡献，但须逐模块证明行为保持，不能把四包存在解释为历史代码已全部搬完。LG-05/07/12 的内部铜执行、旧外部铜替换、来源哈希保护与部分失败恢复属于宿主/typed 链路工作，不能让算法 PR 绕过。

算法贡献默认只交离线数据与结果。真实板适配、独立电气要求、typed 执行、两轮整板布局检查、用户布局确认、保存重载回读及官方 DRC 由维护者按现有 Skill 完成；未完成的现场场景保持未验收。前述三项可作为社区首批认领任务，不要求贡献者一次解决四层、差分、回流或整板生产交付。
