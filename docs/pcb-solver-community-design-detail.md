# PCB 求解社区设计：数学模型与 PR 验收

本页细化[面向贡献者的主设计](pcb-solver-community-design.md)。术语与状态以[概念表](concepts.md#联合布局布线问题)及公开 [PCB 操作契约](../.agents/skills/easyeda-agent/references/pcb-routing.md#联合逃线与模块联动offline-verified)为准。这里描述拟贡献能力，不把设计稿当作已实现或现场通过。

## 数学模型

设模块集合为 `M`，连接需求集合为 `K`。每个模块 `m` 的允许位姿集合 `P_m` 包含平移、旋转和贴装面；固定件只有一个位姿。二元变量 `z[m,p]` 表示选择位姿 `p`，满足 `sum_p z[m,p] = 1`。刚性模块成员共用变换，独立 pin assignment 决定每个从属件的真实焊盘归属。超出板框、侵入禁布区、违反层/锁定/组所有权或器件间距的位姿组合直接排除。

对一个已定布局，将可走区域离散成含铜层、位置、到达方向的图 `G=(V,E)`。边的合法性由完整线段与真实焊盘、已有铜、开槽、禁线区、板边、线宽及净距检查决定，未知几何不能成为合法边。每条需求 `k` 选择从指定起点到终点的路径；不同网络占用冲突的边或相邻走廊不能同时选择。允许换层时，过孔是带孔径、外径和净距条件的跨层边。多端网络需进一步选择一棵连通树，而不是把端点对逐条成功简单相加。

可用二元变量 `x[k,e]` 表示需求 `k` 是否使用有向边 `e`。每个中间节点满足流入量等于流出量；起点净流出为 1，终点净流入为 1。不同网络的冲突边对 `(e,f)` 满足 `x[k,e] + x[j,f] <= 1`。候选位姿改变端点和障碍时，相应边的可用性必须随 `z[m,p]` 重算。这个表达便于检查约束，但不要求贡献者真的建立整数规划模型。

联合模型可视为带几何禁约束的离散位姿选择与多商品路径问题，最坏情况组合爆炸。实现上先固定布局找共同路径，再由 Layout 搜索少量允许位姿并调用同一 Router；可用启发式、回溯或小规模精确求解，但必须保留状态/时间预算。先满足所有硬约束，再按需求比较移动量、过孔数、关键路径长度、总长度和转折；不要把短路或缺测换算为可接受的罚分。搜索耗尽返回 `incomplete`，只有明确违反输入契约的情况返回 `fail`。

## PR 1：固定布局的多需求布线

在 `pkg/pcbrouting` 增加纯 Go 的多需求求解与独立复验接口，沿用单网 `Request`、`Solve`、`Check` 和 `SegmentClear` 的规则。多需求接口必须让调用方用固定快照检查某条候选线相对既有铜及**本候选已选线路**的整段净距；包内不得导入 `internal/app`、Cobra、EDA 类型或文件系统。API 具体命名由 PR 决定，但需让需求 ID、网络、层、线宽、预算、各条路径和失败原因可追踪。检查器从原始输入与完整路径集重新判定，不能信任求解器返回的状态或测量值。

最低验收样例：两网共享狭窄通道时不能分别通过后一起报告成功；换序或局部重寻能完成的板例应给出共同合法路径；不可通过的有限搜索与状态预算耗尽均报告 `incomplete`；重复运行输出一致；输入顺序不应改变需求身份或检查结果。`go test ./pkg/pcbrouting` 通过，并有一个多需求规模的基准数据。此 PR 不负责 EasyEDA 写入、换层、整板自动布线或晶振策略改写。

## PR 2：布局纯计算边界

从 `internal/app/pcb_layout_plan.go` 等现有代码提取与 EasyEDA 对象无关的位姿枚举和候选几何校验。输入保留模块成员、固定轴、允许角度、pad assignment、真实 bbox/pads、板框及 keepout；输出完整位姿候选、被拒原因和客观测量。保留当前 `pcb layout-plan` CLI 与 JSON 兼容，不能为抽包修改现场 Apply/回读规则。测试包含旋转后的真实焊盘坐标、跨层障碍、固定轴、锁定成员、未知几何和输入顺序确定性。

## PR 3：局部联合搜索

Layout 将每个完整位姿候选投影成临时板快照，调用 PR 1 的多需求 Router；同一候选的路径必须共同存在。可动组纳入搜索时，要显式声明器件、原有铜和外部连接的所有权；每次组移动后重新计算受影响连接。输出最多若干完整候选、输入哈希、预算消耗、拒绝原因和每条需求的事实测量。保留独立 `pcb module-check` 对源需求与 fresh 回读的复验；首次现场通过以前状态为 `offline-verified`。

## 与现有工具的边界

`pkg/pcbrouting` 当前只保证单层零过孔、八方向有界 A* 与独立 `Check`；`pcb route solve/check` 负责把 `pcb dump --include-copper` 和网络/层/规则适配给包。Layout 的有限候选生成、联合逃线、晶振保护和回读检查现处于 `internal/app`。首个晶振 schema-v3 现场候选已被 fresh `module-check` 拒绝并回退，不能当作通过样例。所有新算法仍需经过独立几何复验、typed 执行、保存、真实重载、fresh 回读和官方 DRC 才可报告现场完成。
