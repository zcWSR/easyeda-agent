## 场景与判据

| ID | 输入或触发 | 必须观察到的事实 |
|---|---|---|
| F1 整体生成 | 原始需求；测试工程初始快照 | 每个器件有唯一核心/外围归属；选型、全部物理脚、pin→net/NC 与需求逐项对应；direct 保留真实线树；完整区内与纸张候选通过，固定渲染与 compose 使用同一几何，Apply journal 完整。 |
| F2 落图与持久化 | F1 的完整队列 | 实际组件/网络/导线/标记/框/位号/几何与目标逐项对账；逐页 `sch gate --strict` 为 pass；`sch save` 返回 `saved:true`；真实 `doc reload` 后新鲜回读仍一致。导图只辅助找漏项。 |
| L1 核心局部移动 | 保留源 + 新鲜页快照 + 测得的合法 5 raw 目标 | `sch layout-edit --move-core` 重新生成本区；核心和专属外围及附着图元一起移动，其他区组件身份、参数、网络、NC 和几何逐项不变；碰撞或容量不足明确失败，不输出成功队列。 |
| L2 单脚标记修复 | 新鲜回读中确有可归因的旧引线、旧标记与错误 | `--repair-pin` 仅改变指定支路，沿真实引脚外向；问题消失，旧有 findings 与范围外对象不增加或不变。缺少真实前置缺陷则记 `not-run`，不造现场错误凑覆盖。 |
| N1 写前拒绝 | 过期快照、缺归属、direct 被同名标签代替、实例身份/属性缺测等独立夹具 | 各类问题按对象/原因非零失败，失败的离线阶段不产出可 Apply 的完整计划；不得把 `blocked` 或预算耗尽写成设计不可能。 |
| R1 重现与幂等 | 相同源、测量、参数和代码版本重复离线计算 | 哈希和目标几何一致；新鲜回读下重复转换不引入无谓重建；部分写/超时先读实际状态再重算，不盲重放。 |

## 证据与判定

每轮在仓库外或忽略目录保留：原始需求、未改写的官方快照、目标源、测量来源、算法参数
和提交号、SHA-256、完整候选/选中页、固定导图、队列 dry-run、执行 journal、fresh
`sch list`/`connectivity`/`read`、逐页 `layout-lint`/`check`/`bridge-check`/DRC/strict gate、
实例身份与 `uniqueId`/属性、范围外差分，以及 save/reload 后第二份 fresh 回读。
验收报告按场景记录 `pass`、`fail`、`blocked` 或 `not-run`，并给出证据路径和第一条失败对象。
缺测、连接器未加载、宿主持续加载、保存/重载失败一律不能记 `pass`。
