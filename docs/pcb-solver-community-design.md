# PCB 布局布线求解：社区贡献方向

PCB 布局和布线可以写成数学约束问题，适合社区分阶段改进。目标是从一份可复算的板快照和明确需求，生成完整、可检查的候选；求解器找不到结果时说明搜索范围与原因，不能把预算耗尽说成板子无解。

目前已有可独立引用的单网布线包 [`pkg/pcbrouting`](../pkg/pcbrouting/README.md)，支持固定几何下单层、零过孔的有界寻路和独立路径检查。布局候选和多网联合逃线仍主要在 `internal/app`；布局算法尚未整体抽成公开包。社区可以从现有边界出发，不需要接入 EasyEDA 编辑器或操作现场工程。

建议按下面顺序拆成可独立评审的 PR：

1. **固定布局下的多需求协同布线。** 多条线共享同一份障碍与已选路径，失败时允许有限次换序或重寻；输出所有路径或明确的 `incomplete`。独立检查每条路径及路径之间的净距。这是最适合先认领的算法任务。
2. **布局候选内核抽离。** 把模块的允许平移、旋转、固定约束和碰撞检查提成不依赖编辑器的纯计算接口；保留现有 `pcb layout-plan` 的输入、候选和回读语义。抽离本身不扩大功能范围。
3. **局部联合搜索。** 布局候选调用多需求 Router 检查共同通道；在有界预算内尝试替代位姿或可动组，报告每个候选的约束事实、移动量和布线测量。再考虑换层、过孔与整板网络。

贡献者可自由选择 A*、约束规划、整数规划或其他算法。验收看真实约束是否满足、结果是否可复算、失败是否诚实，而不是算法名称或单一总分。硬约束必须全部通过；长度、过孔和移动量只用于比较合法候选。独立复验与官方 DRC、保存重载回读仍分别需要完成。

输入、数学表达、PR 边界和测试样例见[详细设计](pcb-solver-community-design-detail.md)。
