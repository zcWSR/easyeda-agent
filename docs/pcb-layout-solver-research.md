## 结论与现有实现证据

1. 现有有限候选和有预算搜索可以找到可行解，**没有 PCB 布局全局最优或唯一最优保证**。
   相同输入输出相同结果、去掉重复状态，都不构成最优性证明。
2. 宽松几何、估计线长与拥塞适合生成和排序候选，最终必须用真实焊盘、铜面积、净距、
   板框和所有路径共同合法性验收。粗略筛选若会排除合法解，还会影响搜索完整性。
3. 最小移动适用于已有板的局部修复；从零整板布局需要另定目标，不能沿用最小移动排名。
4. 优先验证路由冲突反馈驱动模块让位；多起点模拟退火适合离线质量对照。强化学习暂不
   作为二层 MVP 的实现前提；先借鉴它的实际路由评估方法。
5. MCP/Skill 主要解决数据读取、操作封装、分析与工作流。工具数量和自然语言演示不能
   证明自动布局质量，仍要用相同约束和预算的独立测试比较。

## 建议的职责边界

以下公共边界已用于二层协同求解；存量 auto-place、九维评分和专用模块策略仍通过宿主适配
逐步迁移，不能把新 MVP 表述成所有历史算法均已删除：

| 包 | 目标职责 |
|---|---|
| `pcbmodel` | 宿主无关板、器件、焊盘、铜、规则、所有权、层叠、几何变换 |
| `pcblayout` | 放置、约束、合法化、模块/晶振策略、完整组让位与布局检查/测量 |
| `pcbrouting` | 固定几何下的单网/多网路由、路径优化及独立路径检查 |
| `pcbsolve` | 候选投影、路由反馈、搜索预算、去重、排序及最终独立复验 |

`internal/app` 保留快照/库适配、Cobra、文件输出、渲染和 typed Apply；运行时 PID 映射
留在宿主层。公共包不依赖编辑器、daemon 或 Connector。`pcbsolve.Check` 从原始板和独立
需求复验，不调用 `Solve`、不信任候选自报通过或自报指标。

首版固定装配面，允许原面平移及声明的旋转，支持 TOP/BOTTOM 路径与有预算的通孔。
不增加翻面、差分、等长、自动铺铜。层叠数据从第一版表达有序铜层、信号/平面角色、平面
网络及过孔跨层范围；只有层数的旧数据不推断内层用途。局部逃线已有的换层能力与新的
公共板级联合求解能力必须分别报告，不能互相代替。

## 验证计划

已有相对布局的组合移动按 [开发验证清单](pcb-layout-validation.md) 逐项推进。该清单记录
用户可观察场景与待办，本节保留算法验证设计；自动测试通过不等于场景的现场验收完成。

2026-09-24 的路线避让审查确认这套职责可形成闭环，同时发现固定排网顺序及初始旋转
淘汰会漏解。已补有预算的排网次序回溯和移动后的整体旋转邻域，并以固定布局两网、双组
递归让位/外部端点重算场景核对。具体红绿过程和能力边界见
[运行记录](reviews/2026-09-24-pcb-route-avoidance.md)。这证明有限模型中的避让能力，不把
同层路径枚举、真实带铜模块 Apply 或整板现场验收宣称为完成。

### 1. 先冻结问题、基线和目标

验证三条线：正确性、相同资源下的优化质量、现场持久化一致性。硬约束先成立，软成本
不能换取违规。局部修复对合法候选按下列向量作字典序比较，不合成总分：

`移动组数 → 总位移 → 旋转次数 → 新增过孔 → 实际线长 → 转折数`

从零布局另定目标和测试集，不因摆在初始位置“零移动”就判为好布局。

每次基准保存代码 commit、未提交差异及哈希、原始输入和需求哈希、单位、坐标约定、
规则、搜索配置、随机种子、依赖及机器/线程信息。工作树持续变化时，不只记录 HEAD。
外部格式转换不能静默丢弃固定组、禁布区、铜归属或规则；无法等价转换的案例单列为
unsupported 并解释原因，不混入公平性能比较。

### 2. 典型案例与失败测试

沿用 [现有板案例约定](../internal/app/testdata/boards/README.md) 的原始 board、独立
spec、独立 expect 分离思想；新增求解案例目录在实现时确定，不覆盖已有评分 fixture。
每例记录来源、开始状态、需求及单位、独立期望、验证状态。先写失败测试，再实现，再回归；
期望以约束、连通性和指标边界为主，不复制求解器输出坐标作为答案。

| 案例组 | 必须证明的行为 |
|---|---|
| 基础几何 | 非对称封装绕 anchor 旋转正确；成员、焊盘和归属内部铜同步变换 |
| 机械约束 | 板边接口、开口、安装孔、禁放区、固定轴保持；凹板框不能只查 bbox |
| 核心与外围 | MCU 去耦、串联电阻、LED、LDO/DCDC、晶振遵循明确所有权 |
| 共同通道 | 两网分别可达但不能同时通过时拒绝成功；先选路径占用后续网络空间 |
| 路由驱动让位 | 没有器件重叠但线路受阻，依据实际冲突移动完整组；预算耗尽不作为阻挡归因 |
| 多组联动 | 阻挡组递归让位、遇固定组回溯；每次移动重算外部连接，状态去重避免循环 |
| 二层换层 | TOP 受阻时按规则走 BOTTOM；检查过孔铜面积、孔径、净距及网络预算 |
| 层限制 | TOP-only 不换层；通孔焊盘跨层障碍正确；异面器件占用分别判断 |
| 电源与既有铜 | 局部回流、内部铜、固定连接不被破坏；同名 GND 不等于物理连通 |
| 独立复验 | 篡改路径、漏移动成员、未知铜、缺测、旧快照均被识别；不信自报指标 |
| 宽松估计反例 | 粗略几何通过而精确净距失败时淘汰；估计线长降低但联合布线失败时不得推荐 |
| 资源与失败 | 布局、联合路由及单次寻路共享总预算；取消/超时保留已经找到且通过复验的合法候选 |

变形测试使用网格对齐平移、90° 旋转及输入重排；板框、端点、方向约束等同步变换，层
约束保持等价。检查电气结论和对应指标，不要求等价最优解具有相同坐标或输出排序。
规模测试分小场景、几十器件、已有大型参考板，记录时间、状态和内存。

### 3. 独立的小型精确参照

先用 2～4 个移动组、每组少量合法位置/旋转、小型离散路由图建立穷举参照，不把大型
精确优化器开发作为 MVP 的前置项目。穷举同时考虑布局与共同路径，约束与被测模型一致：
层、线宽、净距、路径域、过孔上限和目标向量均明确。

参照不调用生产 `Solve`；极小图形尽量使用独立几何判断或手工可审查的合法路径集合，
避免双方共用同一缺陷。只有穷举完成才能证明该有限模型最优或不可行；预定义路径集合的
穷举只证明该集合内的结论。预算耗尽不给证明，也不外推到连续空间。

指定的极小验收例要求被测算法找到已知可行解，并达到参照的最优向量；多个等价解均可
接受。一般规模案例只报告相对质量，不能因为几个小例最优就声明求解器全局最优。

### 4. 同预算策略对照与消融

| 策略 | 比较目的 |
|---|---|
| 冻结的现有有限枚举 | 兼容性、成功率和性能基线 |
| 冲突反馈＋模块让位 | 本轮主要改进策略 |
| 固定种子的多起点模拟退火 | 离线搜索质量对照；不是直接采纳 SA-PCB |

比较布局策略时使用同一个 Router；比较 Router 时使用同一批固定布局。历史端到端结果
与这种受控对照分别保存。增加关闭路由反馈的消融，以及粗筛启用/关闭的对照，定位收益
是否来自真实冲突反馈，观察粗筛是否漏解。

首次实验建议使用种子 `0..9`、总预算 `1/10/60 秒`，相同机器和线程，统计整个布局、
路由与复验耗时；另记录各阶段耗时。以上是待冻结的默认配置，不是实测结果。正式比较
前声明主要指标、非退化条件与调整预算的原因，不能看完成绩再挑种子、案例或阈值。

报告联合布通率、硬约束违规数、目标向量、状态数、耗时和峰值内存，随机策略展示全部
种子及中位数/较差分位数。指标只在合法候选上比较；失败没有线长不能当作零线长。
missing/incomplete、unsupported、invalid、timeout/canceled 分开解释，保留全部失败案例。
候选是否可行、搜索是否结束、是否有模型内最优证明分别报告：搜索未完成也可能已有合法
候选；规定只保留三个候选也不意味着后面没有更优候选。

改进结论至少要求必测正确性全过、必测案例布通率不退化、预声明的质量或资源指标有改善；
其他代价的变化同时列出。没有优势或出现取舍就据实报告，不以综合布局分数上升代替。

### 5. 二层 MVP 的验收

场景包含两条竞争通道的网络、一个多成员可移动组和固定障碍：

1. 通过极小独立参照证明原布局在声明模型中不能同时满足两网；一次寻路失败不足以证明。
2. 求解记录输出实际阻挡对象、位置和冲突网络，依据反馈移动完整组并重算外部连接。
3. 独立检查确认最终两网共同合法，固定对象及未移动对象保持，所有成员和内部铜一致。
4. 输出原布局、失败候选、最终候选的整板与局部 SVG，显示真实焊盘、既有铜、线宽、净距、
   过孔和移动原因。候选 JSON、渲染及 Apply 消费同一投影，像素不作为连通性证据。
5. 保留最多三个合法候选及事实指标；同时报告搜索是否完成，不声称全局最优或全局无解。

## 交付、执行顺序与能力边界

| 顺序 | 交付与退出条件 |
|---|---|
| A：抽包兼容性 | 迁移现有布局算法/测试，旧 CLI 与 JSON 保持兼容，外部 Go 测试可调用公共包；与算法改进结果分开验收 |
| B：二层 TDD | 典型正负例、极小精确参照、闭环 MVP、受控策略对照和消融；报告失败与不完整搜索 |
| C：现场一致性 | 参数化 ceshi 复现、两轮布局自检、用户确认、路由应用及独立回读；证据不足不升级状态 |
| D：多层分阶段扩展 | 纳入统一 `pcbsolve` 设计；按 [A4](pcb-solver-community-design-detail.md#a4多层布局布线协调) 分模型/独立检查、多层共同搜索、平面/回流案例推进。当前仍仅二层求解，多层验收待完成 |

交付物为版本化案例与独立期望、机器可读运行报告、前后 SVG、基线/策略对照及能力矩阵。
报告应能追溯输入、代码、规则、预算、验证器和渲染/Apply 的同一候选身份。

现有 [布局基准测试](../internal/app/pcb_layout_benchmark_test.go) 和大型参考板主要证明
评分校准及兼容性，不直接作为布通或最优性标准；仅当板数据和独立需求完整时，才纳入
共同布通率统计。商业原始板和私有日志按案例约定留在本地，不作为公开数据提交。

实施时运行相关包测试、`go test ./...`、`make layout-calibrate`、`make skill-check`；
修改协作入口时运行 `make agent-check`。`make lint-test` 是原理图规则测试，不能代替
PCB 求解回归。上述命令为实施计划，不代表本次已执行。

涉及仓库规定的布局检查内核、layout-lint、autosave、design-flow 或 Connector 回归时，
按 [AGENTS.md](../AGENTS.md) 使用 [ESP32 原始需求](../esp32MiniRequire.md) 第一节执行
完整回归，不输入加工过的 BOM/网表答案。此兼容性端到端证据与新四层求解器验收分开，
现场缺口单列；模型能表达四层不等于已支持四层联合求解。
